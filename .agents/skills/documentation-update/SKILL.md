# Documentation update
1. Identify affected readers: users, developers, operators, and architectural reviewers.
2. Derive statements from verified code, accepted decisions, and test evidence. Mark unresolved assumptions.
3. Update the product brief for behavior, architecture contract and diagrams for structure, runbooks for failure/recovery, and ADRs for significant choices.
4. Keep examples executable or clearly illustrative; remove obsolete instructions.
5. Check links, command accuracy, version consistency, and agreement between documentation and implementation.
6. In the handoff, list updated docs and explicitly note any documentation debt.
