# Task handoff
Use the exact headings in `docs/engineering/COMMUNICATION.md`. Report outcome, user-visible changes, touched components, architecture status, commands and results, documentation, operational risks, approvals and next steps. Include commit or PR reference when available. Explicitly distinguish passed, failed, skipped, unavailable and not-run checks. Do not claim another reviewer or guardian approved the change unless independently recorded.
